## Аутентификация

Эти эндпоинты **не требуют** заголовка `Authorization`.

---

### Регистрация

Создаёт нового пользователя.

`POST /api/auth/register`


**Заголовки:**

| Заголовок | Значение |
|-----------|----------|
| `Content-Type` | `application/json` |

**Тело запроса:**

| Поле | Тип | Обязательное | Ограничения | Описание |
|------|-----|-------------|-------------|----------|
| `login` | string | Да | Минимум 3 символа | Логин пользователя |
| `password` | string | Да | Минимум 8 символов | Пароль |

**Пример запроса:**


POST /api/auth/register HTTP/1.1
Host: localhost:5000
Content-Type: application/json
```json
{
"login": "Login123",
"password": "Str0ng!Pass1"
}
```


**Успешный ответ — `201 Created`:**

```json
{
  "id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "login": "Login123"
}
```

Ошибки:
400 - ValidationError, "Не удалось зарегистрировать пользователя" (Пустой логин, слабый пароль, невалидный формат)
409 - LoginAlreadyExists, "Пользователь с таким логином уже существует" (Такой логин уже зарегистрирован)

Пример тела ошибки 400:
```json
{
  "statusCode": 400,
  "error": "ValidationError",
  "message": "Не удалось зарегистрировать пользователя",
  "details": [
    { "field": "login", "message": "Логин обязателен" },
    { "field": "password", "message": "Пароль должен содержать минимум 8 символов" }
  ]
}
```

### Логин

Проверяет учётные данные и возвращает пару токенов.

```
POST /api/auth/login
```

**Заголовки:**

| Заголовок | Значение |
|-----------|----------|
| `Content-Type` | `application/json` |

**Тело запроса:**

| Поле | Тип | Обязательное |  Описание |
|------|-----|--------------|----------|
| `login` | string | Да | Логин пользователя |
| `password` | string | Да | Пароль |

**Пример запроса:**

```
POST /api/auth/login HTTP/1.1
Host: localhost:5000
Content-Type: application/json

{
  "login": "Login123",
  "password": "Str0ng!Pass1"
}
```

**Успешный ответ — 200 OK:**
```
{
  "accessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiJhMWIyYzNkNC1lNWY2LTc4OTAtYWJjZC1lZjEyMzQ1Njc4OTAiLCJlbWFpbCI6InVzZXJAZXhhbXBsZS5jb20iLCJleHAiOjE3MzU1MDAwMDB9.abc123signature",
  "refreshToken": "dGhpcyBpcyBhIHJlZnJlc2ggdG9rZW4gZm9yIHVzZXIgYTEyMzQ1",
  "expiresIn": 1800
}
```

| Поле | Тип | Что делать клиенту |
|------|-----|--------------------|
| accessToken | string | Сохранить в память. Подставлять в Authorization: Bearer <accessToken> каждого запроса |
| refreshToken | string | Сохранить в защищённое хранилище. Использовать только для /api/auth/refresh |
| expiresIn | int | Время жизни accessToken в секундах. По истечении — идти на refresh |

**Ошибки:**

| Код | error| Причина |
|-----|------|---------|
| 400 | ValidationError | Пустое тело запроса |
| 401 | InvalidCredentials | Неверный логин или пароль|

**Пример тела ошибки 401:**
```
{
  "statusCode": 401,
  "error": "InvalidCredentials",
  "message": "Неверный логин или пароль",
  "details": null
}
```

### Обновление токенов

Используется, когда `accessToken` протух и сервер вернул `401`
Клиент отправляет `refreshToken` и получает новую пару токенов

```
POST /api/auth/refresh
```

**Заголовки:**

| Заголовок | Значение |
|-----------|----------|
| `Content-Type` | `application/json` |

**Тело запроса:**

| Поле | Тип | Обязательное | Описание |
|------|-----|-------------|----------|
| `refreshToken` | string | Да | Токен, полученный при логине или предыдущем refresh |

**Пример запроса:**

```
POST /api/auth/refresh HTTP/1.1
Host: localhost:5000
Content-Type: application/json

{
  "refreshToken": "dGhpcyBpcyBhIHJlZnJlc2ggdG9rZW4gZm9yIHVzZXIgYTEyMzQ1"
}
```

**Успешный ответ — `200 OK`:**

```json
{
  "accessToken": "eyJhbGciOiJIUzI1NiIs... (новый)",
  "refreshToken": "bmV3IHJlZnJlc2ggdG9rZW4... (новый)",
  "expiresIn": 1800
}
```

При каждом refresh старый `refreshToken` становится недействительным.
Клиент обязан сохранить новый `refreshToken` и использовать в следующий раз именно его.

**Ошибки:**

| Код | `error` | Когда | Что делать клиенту |
|-----|---------|-------|--------------------|
| 400 | `ValidationError` | Пустое тело | Исправить запрос |
| 401 | `InvalidRefreshToken` | `refreshToken` невалиден, отозван или протух | Удалить токены, показать экран логина |

**Пример тела ошибки 401:**

```json
{
  "statusCode": 401,
  "error": "InvalidRefreshToken",
  "message": "Сессия истекла. Войдите снова",
  "details": null
}
```

## Заметки

Все эндпоинты в этом разделе **требуют** заголовок авторизации:

```
Authorization: Bearer <accessToken>
```

Если `accessToken` протух, сервер вернёт `401`.
Обработка описана в [Обновление токенов](#обновление-токенов).

---

### Список заметок

Возвращает заметки текущего пользователя с поддержкой фильтрации и пагинации.

```
GET /api/notes
```

**Заголовки:**

| Заголовок | Значение |
|-----------|----------|
| `Authorization` | `Bearer <accessToken>` |

**Query-параметры:**

| Параметр | Тип | Обязательный | Описание |
|----------|-----|-------------|----------|
| `since` | string | Нет | Вернуть только заметки, у которых `updatedAt > since`. Используется для дельта-синхронизации |

**Пример запроса — все заметки:**

```
GET /api/notes HTTP/1.1
Host: localhost:5000
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
```

**Пример запроса — дельта-синхронизация:**

```
GET /api/notes?since=2026-10-28T10:00:00Z HTTP/1.1
Host: localhost:5000
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
```

**Успешный ответ — `200 OK`:**

```json
{
  "items": [
    {
      "id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
      "title": "Список покупок",
      "content": "Молоко, хлеб, яйца",
      "isDeleted": false,
      "createdAt": "2026-10-28T09:00:00Z",
      "updatedAt": "2026-10-28T14:30:00Z",
      "version": 3
    },
    {
      "id": "b2c3d4e5-f6a7-8901-bcde-f12345678901",
      "title": "Идеи для проекта",
      "content": "Заметки с синхронизацией, офлайн-режим",
      "isDeleted": false,
      "createdAt": "2026-10-29T08:00:00Z",
      "updatedAt": "2026-10-29T10:15:00Z",
      "version": 1
    }
  ],
  "totalCount": 42
}
```

| Поле | Тип | Описание |
|------|-----|----------|
| `items` | array | Массив заметок. Может быть пустым `[]` |
| `totalCount` | int | Общее количество заметок |

**Примечание:** удалённые заметки (`isDeleted: true`) **не** попадают в этот список. Для них есть отдельный эндпоинт [Список удалённых заметок](#список-удалённых-заметок).

**Ошибки:**

| Код | `error` | Когда |
|-----|---------|-------|
| 400 | `ValidationError` | Формат даты неверный |
| 401 | `Unauthorized` | Токен отсутствует или протух |

### Получить одну заметку

Возвращает заметку по идентификатору.

```
GET /api/notes/{id}
```

**Заголовки:**

| Заголовок | Значение |
|-----------|----------|
| `Authorization` | `Bearer <accessToken>` |

**Path-параметры:**

| Параметр | Тип | Описание |
|----------|-----|----------|
| `id` | string (GUID) | Идентификатор заметки |

**Пример запроса:**

```
GET /api/notes/a1b2c3d4-e5f6-7890-abcd-ef1234567890 HTTP/1.1
Host: localhost:5000
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
```

**Успешный ответ — `200 OK`:**

```json
{
  "id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "title": "Список покупок",
  "content": "Молоко, хлеб, яйца",
  "isDeleted": false,
  "createdAt": "2026-10-28T09:00:00Z",
  "updatedAt": "2026-10-28T14:30:00Z",
  "version": 3
}
```

**Ошибки:**

| Код | `error` | Когда |
|-----|---------|-------|
| 401 | `Unauthorized` | Токен отсутствует или протух |
| 404 | `NotFound` | Заметка с таким `id` не существует или принадлежит другому пользователю |

**Пример тела ошибки 404:**

```json
{
  "statusCode": 404,
  "error": "NotFound",
  "message": "Заметка не найдена",
  "details": null
}
```

Сервер возвращает `404` и в том случае, если заметка существует, но принадлежит другому пользователю. Это сделано намеренно, чтобы не раскрывать чужие идентификаторы.

### Создать заметку

Создаёт новую заметку для текущего пользователя.

```
POST /api/notes
```

**Заголовки:**

| Заголовок | Значение |
|-----------|----------|
| `Authorization` | `Bearer <accessToken>` |
| `Content-Type` | `application/json` |

**Тело запроса:**

| Поле | Тип | Обязательное | Ограничения | Описание |
|------|-----|-------------|-------------|----------|
| `title` | string | Да | 1–200 символов | Заголовок заметки |
| `content` | string | Нет | до 100_000 символов | Текст заметки. Если не передан — пустая строка |

Поля `id`, `createdAt`, `updatedAt`, `version`, `isDeleted` **не отправляются**. Сервер генерирует их сам.

**Пример запроса:**

```
POST /api/notes HTTP/1.1
Host: localhost:5000
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
Content-Type: application/json

{
  "title": "Новая заметка",
  "content": "Текст заметки"
}
```

**Успешный ответ — `201 Created`:**

```json
{
  "id": "c3d4e5f6-a7b8-9012-cdef-123456789012",
  "title": "Новая заметка",
  "content": "Текст заметки",
  "isDeleted": false,
  "createdAt": "2026-10-29T12:00:00Z",
  "updatedAt": "2026-10-29T12:00:00Z",
  "version": 1
}
```

Клиент должен сохранить возвращённый `id` в локальную БД и связать с ним локальную запись.

**Ошибки:**

| Код | `error` | Когда |
|-----|---------|-------|
| 400 | `ValidationError` | Пустой `title`, превышена длина |
| 401 | `Unauthorized` | Токен отсутствует или протух |

**Пример тела ошибки 400:**

```json
{
  "statusCode": 400,
  "error": "ValidationError",
  "message": "Не удалось создать заметку",
  "details": [
    { "field": "title", "message": "Заголовок обязателен" }
  ]
}
```

### Обновить заметку

Обновляет существующую заметку. Использует **оптимистичную блокировку**: клиент обязан передать текущую `version`, которую он получил ранее. Если на сервере версия уже изменилась, сервер вернёт `409 Conflict`.

```
PUT /api/notes/{id}
```

**Заголовки:**

| Заголовок | Значение |
|-----------|----------|
| `Authorization` | `Bearer <accessToken>` |
| `Content-Type` | `application/json` |

**Path-параметры:**

| Параметр | Тип | Описание |
|----------|-----|----------|
| `id` | string (GUID) | Идентификатор заметки |

**Тело запроса:**

| Поле | Тип | Обязательное | Ограничения | Описание |
|------|-----|-------------|-------------|----------|
| `title` | string | Да | 1–200 символов | Новый заголовок |
| `content` | string | Нет | до 100 000 символов | Новый текст |
| `version` | int | Да | ≥ 1 | Версия заметки, которую клиент получил при последнем чтении |

Поле `version` нужно для обнаружения конфликтов. Клиент **обязан** передать ту версию, которую он последний раз получил с сервера. Если клиент создаёт заметку локально и отправляет впервые — это `POST`, а не `PUT`.

**Пример запроса:**

```
PUT /api/notes/a1b2c3d4-e5f6-7890-abcd-ef1234567890 HTTP/1.1
Host: localhost:5000
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
Content-Type: application/json

{
  "title": "Обновлённый заголовок",
  "content": "Обновлённый текст",
  "version": 3
}
```

**Успешный ответ — `200 OK`:**

```json
{
  "id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "title": "Обновлённый заголовок",
  "content": "Обновлённый текст",
  "isDeleted": false,
  "createdAt": "2026-10-28T09:00:00Z",
  "updatedAt": "2026-10-29T15:45:00Z",
  "version": 4
}
```

Обрати внимание: `version` в ответе увеличился. Клиент должен сохранить новую версию и использовать её при следующем обновлении.

**Ошибки:**

| Код | `error` | Когда | Что делать клиенту |
|-----|---------|-------|--------------------|
| 400 | `ValidationError` | Пустой `title`, нет `version` | Показать ошибки валидации |
| 401 | `Unauthorized` | Токен отсутствует или протух | Делать Refresh и отправлять снова |
| 404 | `NotFound` | Заметка не найдена или чужая | Удалить локально или показать ошибку |
| 409 | `Conflict` | `version` не совпадает с серверной | См. ниже |

**Пример тела ошибки 409:**

```json
{
  "statusCode": 409,
  "error": "Conflict",
  "message": "Заметка была изменена на сервере. Получите актуальную версию",
  "details": null
}
```

**Что делать клиенту при 409:**

1  Запросить актуальную версию: `GET /api/notes/{id}`
2. Перезаписать локальную серверной (для учебного проекта
   достаточно второго варианта)

### Удалить заметку

Помечает заметку как удалённую (мягкое удаление).
Заметка не удаляется из базы физически, а получает `isDeleted: true`.
Это нужно для синхронизации: другие устройства должны узнать, что заметка была удалена.

```
DELETE /api/notes/{id}
```

**Заголовки:**

| Заголовок | Значение |
|-----------|----------|
| `Authorization` | `Bearer <accessToken>` |

**Path-параметры:**

| Параметр | Тип | Описание |
|----------|-----|----------|
| `id` | string (GUID) | Идентификатор заметки |

**Пример запроса:**

```
DELETE /api/notes/a1b2c3d4-e5f6-7890-abcd-ef1234567890 HTTP/1.1
Host: localhost:5000
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
```

**Успешный ответ — `200 OK`:**

```json
{
  "id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "title": "Список покупок",
  "content": "Молоко, хлеб, яйца",
  "isDeleted": true,
  "createdAt": "2026-10-28T09:00:00Z",
  "updatedAt": "2026-10-29T16:00:00Z",
  "version": 5
}
```

Заметка возвращается с `isDeleted: true`, чтобы клиент мог убедиться, что удаление прошло, и обновить локальную БД.

**Ошибки:**

| Код | `error` | Когда |
|-----|---------|-------|
| 401 | `Unauthorized` | Токен отсутствует или протух |
| 404 | `NotFound` | Заметка не найдена, уже удалена или принадлежит другому пользователю |

### Список удалённых заметок

Возвращает заметки текущего пользователя, у которых `isDeleted: true`.
Нужен для синхронизации: клиент, который был офлайн, должен узнать,
какие заметки были удалены на других устройствах.

```
GET /api/notes/deleted
```

**Заголовки:**

| Заголовок | Значение |
|-----------|----------|
| `Authorization` | `Bearer <accessToken>` |

**Query-параметры:**

| Параметр | Тип | Обязательный | По умолчанию | Описание |
|----------|-----|-------------|-------------|----------|
| `since` | string (ISO 8601) | Нет | — | Вернуть удалённые заметки, у которых `updatedAt > since` |

**Пример запроса:**

```
GET /api/notes/deleted?since=2026-10-28T00:00:00Z HTTP/1.1
Host: localhost:5000
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
```

**Успешный ответ — `200 OK`:**

```json
{
  "items": [
    {
      "id": "d4e5f6a7-b8c9-0123-def0-234567890123",
      "title": "Старая заметка",
      "content": "Удалённый текст",
      "isDeleted": true,
      "createdAt": "2026-10-20T10:00:00Z",
      "updatedAt": "2026-10-28T11:30:00Z",
      "version": 4
    }
  ],
  "totalCount": 1
}
```

Клиент использует этот список, чтобы удалить соответствующие записи из локальной БД при синхронизации.

**Ошибки:**

| Код | `error` | Когда |
|-----|---------|-------|
| 400 | `ValidationError` | Неверный формат даты и времени |
| 401 | `Unauthorized` | Токен отсутствует или протух |

## Сводная таблица кодов ответов

| Код | `error` | Где встречается | Что делать клиенту |
|-----|---------|----------------|--------------------|
| 200 | — | Все успешные запросы, кроме создания | Обработать данные |
| 201 | — | `register`, `POST /notes` | Обработать данные |
| 400 | `ValidationError` | Любой эндпоинт | Показать `details` пользователю |
| 401 | `Unauthorized` | Любой эндпоинт с `Auth: Да` | Refresh → повторить запрос |
| 401 | `InvalidCredentials` | `login` | Показать «неверный логин/пароль» |
| 401 | `InvalidRefreshToken` | `refresh` | Удалить токены, экран логина |
| 404 | `NotFound` | `GET/PUT/DELETE /notes/{id}` | Показать ошибку или удалить локально |
| 409 | `LoginAlreadyExists` | `register` | Показать 'login уже занят' |
| 409 | `Conflict` | `PUT /notes/{id}` | Получить актуальную версию, разрешить конфликт |
| 500 | `InternalError` | Любой эндпоинт | Ошибка на стороне сервера, записать в логи или отправить репорт |
